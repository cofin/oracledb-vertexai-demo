# Operations Patterns

<!-- truth: start -->
- Local development (`make start-infra` / `uv run python manage.py infra start` in `tools/oracle/database.py` and `tools/oracle/adb.py`) defaults to `container-registry.oracle.com/database/adb-free:latest-26ai` (`cymbal-adb-free`), which bundles Oracle AI Database 26ai with automatic vector memory management, APEX `26.1`, and ORDS `26.3` on `https://localhost:8443/ords/apex`. `AdbBootstrap` exports the container mTLS wallet into `.envs/tns` (`myatp_low` on `:1522` via `extract_oracle_wallet_zip` and `parse_tnsnames_ora`), normalizes `tnsnames.ora` and `sqlnet.ora` for `localhost:1522`, and provisions user `APP`, ORDS `ENABLE_SCHEMA`, and the `COFFEE` APEX workspace.
- Setting `ORACLE_CONTAINER_FLAVOR=free` selects lightweight `gvenzl/oracle-free:latest` (`oracle-free-db` on `:1521/freepdb1` without APEX/ORDS or mTLS wallets) for `make test-integration`. On `free`, `tools/oracle/on_init/00_configure_vector_memory.sql` configures `ALTER SYSTEM SET vector_memory_size = 512M SCOPE = SPFILE` within Oracle Free Edition's 2 GB SGA+PGA cap before migrations create HNSW `ORGANIZATION INMEMORY NEIGHBOR GRAPH` indexes (`V$SGAINFO` reports `Vector Memory Area`).
- `VECTOR(N, FLOAT32)` DDL, `AISettings.embedding_dimensions` (`3072`), and committed fixture vector lengths (`src/app/db/fixtures/*.json*`) are co-versioned. Do not mix lower-dimensional examples into this application.
- `ORACLE_AGENT_IN_MEMORY` and `ORACLE_LITESTAR_SESSION_IN_MEMORY` default to `True` in `DatabaseSettings` (`src/app/lib/settings/_database.py`) so SQLSpec session and queue extension tables enable Oracle `INMEMORY` where licensed.
- `OracleAsyncConfig` requires `connection_config=`; legacy `pool_config=` wiring silently drops credentials and surfaces as `DPY-4001`.
- APEX 26.1 Vertex AI provisioning (`uv run python manage.py infra apex configure-vertex` in `tools/oracle/apex_vertex.py`) supports two connectivity modes for the `COFFEE_VERTEX_AI` (`GENERIC_OPENAI`) Generative AI Service:
  - Direct Vertex AI (`--mode direct`): targets `https://aiplatform.googleapis.com/v1/projects/<project>/locations/global/endpoints/openapi` (`model="google/gemini-3.8-flash"`, `VERTEX_AI_LOCATION=global`), grants `DBMS_NETWORK_ACL_ADMIN` host ACEs for `aiplatform.googleapis.com:443` to `APP` and `APEX_NNNNNN`, and stores a Google OAuth2 Bearer access token (~60m expiry) in `VERTEX_AI_CRED` (refreshed via `uv run python manage.py infra apex configure-vertex --mode direct --refresh-token --verify`).
  - Litestar OpenAI-Compatible Gateway (`--mode gateway`): targets `ApexAIController` (`GET /api/apex/ai/v1/models` and `POST /api/apex/ai/v1/chat/completions` in `src/app/domain/products/controllers/_apex_ai.py`, `http://host.docker.internal:8000/api/apex/ai/v1`, optional `APEX_GATEWAY_API_KEY`), reusing Litestar's auto-refreshing ADC and Context-Aware Access mTLS credentials without manual token rotation.
- APEXlang lifecycle commands require SQLcl `26.1.2+` and live under `uv run python manage.py infra apex generate|export|validate|import` (`tools/oracle/apex_lang.py`). Keep source-controlled APEX assets under `src/apex/cymbal-coffee-ops/` with SQLcl's hyphenated directories (`shared-components/`, `supporting-objects/`).
- Keep `src/apex/cymbal-coffee-ops/` pages backed by local SQL queries against `APP` tables and `APEX_AI.GENERATE(p_service_static_id => 'COFFEE_VERTEX_AI')` rather than REST Data Sources referencing an external `restDataSourceServer`, so `apex import` (`project import`) never hits `ORA-02291: WWV_WEBSRC_MODULE_RSERVER_FK`.
- Demo media pipelines (`tools/demos/shell.py`, `tools/demos/web.py`):
  - `make docs-demos-shell` (`uv run python manage.py demos shell`) runs VHS `.tape` files under `docs/_tapes/` with `ROD_BROWSER_BIN` pointing to an executable Chromium binary and `VHS_NO_SANDBOX=true` on Linux workstations.
  - `make docs-demos-web` (`uv run --group demos python manage.py demos web`) records headless Playwright APEX `26.1` walkthroughs using `ignore_https_errors=True` for `adb-free`'s self-signed `:8443` TLS certificate and closes the browser context (`context.close()`) before `ffmpeg` transcoding so `.webm` buffers flush completely before generating `.mp4` and `.gif` artifacts under `docs/_static/demos/`.
- Logging uses `src/app/lib/log/` processors, configures Litestar and Granian defaults in `src/app/config.py`, suppresses `asyncio` and `_granian` noise filters, and filters known `google_genai` and `authlib` deprecation warnings.
- PyApp onefile releases (`tools/scripts/build-onefile-package.sh`) build assets and wheel, bundle Python 3.13 dependencies with `tools/bundler.py`, install under the XDG config path (`~/.config/cymbal-coffee`), and compile Linux launchers with `cargo zigbuild --release --target <arch>-unknown-linux-gnu.2.17`.
- `make build-onefile` forces `UV_PYTHON` and `PYAPP_BUILD_PYTHON` to the explicit CPython 3.13 build interpreter while `make install` pins local `.python-version` (gitignored) to `3.12` for local development.
- Release containers wrap the onefile binary from the distroless Dockerfile at `tools/deploy/docker/Dockerfile`, copying `dist/coffee-*-linux-gnu` and exposing `/app/wallet` with `TNS_ADMIN` and `WALLET_LOCATION` pointed there for read-only Oracle wallet mounts.
- Release CI builds onefiles and containers on native architecture runners (`ubuntu-24.04` for x86_64/amd64 and `ubuntu-24.04-arm` for aarch64/arm64) rather than emulation, smoke-checking `coffee upgrade --help`.
- Docs publish via `make docs` (`uv run --group docs sphinx-build -W --keep-going -b html docs docs/_build/html`) and `.github/workflows/docs.yml`. Do not mock core runtime imports (`oracledb`, `sqlspec`, `google.auth`, `google.genai`, `litestar`, `dishka`, `msgspec`) in `docs/conf.py` because SQLSpec inspects `oracledb.__version__` at import time.
- Docs in `docs/` use the `sphinx-immaterial` theme with custom admonitions (`tour-stop`, `oracle-internals`, `agent-detail` in `docs/conf.py`), organizing pages across guided walkthroughs and labs (`docs/index.md`, `docs/tour.md`, `docs/lab.md`, `docs/lab-gce.md`, `docs/lab-cloud-run.md`, `docs/mcp-antigravity.md`, `docs/maps.md`), architecture deep dives (`docs/concepts/{vector-search,rag,agent-flow}.md`), and reference pages (`docs/reference/{quickstart,cli,api,internals,developers,brand-assets}.md`).
- Code embeds in `docs/` use `literalinclude` (`:pyobject:` for Python and `docs:start-<name>` / `docs:end-<name>` anchors for SQL) with a brief framing paragraph naming the file or symbol and its role.
- Autodoc scope (`docs/reference/api.md`) stays focused on HTTP controllers (`:no-members:`), runtime and routing classes (`AgentOrchestrationService`, `AgentRuntime`, `GeminiModelClient`, `HybridRouteResolver`, `GroundedRouteService`), base and domain services (`OracleAsyncService`, `OracleLoaderService`, `ProductService`, `StoreService`, `OracleVectorSearchService`, `VertexAIService`, `CacheService`, `MetricsService`), and schema modules (`app.lib.schema` and `app.domain.{chat,products,system}.schemas`) rather than CLI commands, settings dataclasses, or IoC providers.
- `AsyncTestClient` must be entered with `async with AsyncTestClient(app) as client:` so the Litestar lifespan opens and closes Dishka containers and Oracle connection pools cleanly.
- Dual HTMX and JSON endpoints parse the request body directly (`await request.json()` or `await request.form()`) rather than declaring a typed JSON `data:` body parameter that would reject HTMX form posts.
- `hx-ext="litestar"` belongs on JSON-templating surfaces (`src/app/domain/web/templates/base.html.j2`); scope partial-HTML swap containers out with `hx-ext="ignore:litestar"` so the extension does not intercept HTML fragments.
- The chat form (`src/resources/chat-stream.js`) must capture `new FormData(form)` before disabling input controls during submission, because disabled controls are omitted from `FormData`.
- Cached chat responses store only product-lookup `sql_phases`; at read time the cache hit wraps them in a fresh `get-cached-response` phase.
- Streaming `/api/chat/stream` exception handling lives inside the async generator (`src/app/domain/chat/controllers/_chat.py`): log expected credential or AI-unavailability failures with `logger.awarning()` (yielding setup guidance) and unexpected exceptions with `logger.aexception()` (yielding a generic sanitized SSE `error` frame) because HTTP exception middleware cannot intercept errors after SSE headers have been sent.
- If `make lint` fails during `frontend-typecheck` due to missing `tsc`, install frontend dependencies in `src/resources/` via `uv run python manage.py assets install`.
- Resolve `uv.lock` against the public PyPI index (`https://pypi.org/simple`, configured automatically by `tools/scripts/setup-env.sh` on internal Linux workstations) so public CI builds never hit 401 authentication errors.
- For Oracle Exadata and 26ai DBA agent workflows, connect with account-level read-only diagnostic users (`ALTER USER ... READ ONLY;` enforcing `ORA-28194`), expose vetted `GV$SQL`, `GV$ACTIVE_SESSION_HISTORY`, `V$SYSSTAT`, and `V$RMAN_BACKUP_JOB_DETAILS` queries via MCP Toolbox or audited `sql -mcp`, and gate any DDL/DML remediation behind deterministic SQL threshold checks and human approval.
