# Architecture Patterns

<!-- truth: start -->
- Litestar app setup stays thin: `src/app/server/` wires plugins, middleware, routes, and templates; domain packages own behavior.
- Domain packages organize implementation modules as private `_*` files inside `controllers/`, `services/`, and `schemas/` subpackages (plus `runtime/`, `protocols/`, `mcp/`, and `a2a/` under `src/app/domain/ai/`), re-exporting public symbols exclusively through each package's `__init__.py` (`__all__`). Cross-domain imports go through package exports, never deep private `_*` modules.
- Dishka uses modular providers in `src/app/ioc/` (`_config.py`, `_database.py`, `_ai.py`, `_domain.py`) assembled via `create_container()` and `get_providers()` in `src/app/ioc/__init__.py`: `ConfigProvider`, `DBProvider`, `AIProvider`, and `DomainServiceProvider`.
- `ConfigProvider` owns APP-scoped `Settings`, sub-settings (`AppSettings`, `ServerSettings`, `DatabaseSettings`, `AISettings`, `ChatSettings`, `ViteSettings`, `MapsSettings`, `LogSettings`, `OpenTelemetrySettings`, `QueueSettings`), and `SQLFileLoader` (`default_sql_loader()`).
- `DBProvider` owns APP-scoped `OracleAsyncConfig` (`DatabaseSettings.get_config()`) and `QueueService`, plus REQUEST-scoped `OracleAsyncDriver`; `src/app/config.py` owns lazy PEP 562 `SQLSpec` (`db_manager`), `db`, `queue_db`, and `queue` wiring.
- `AIProvider` owns APP-scoped external AI integrations and native runtime stores: `google.genai.Client` (with `_VertexFallbackCredentials` and Context-Aware Access mTLS transport detection), `GeminiModelClient`, `AgentRuntime`, `AgentStreamService`, `SpecTree`, `PersonaManager`, `OracleSessionStore`, and `OracleEventStore`.
- `DomainServiceProvider` owns REQUEST-scoped domain services: `ProductService`, `StoreService`, `CacheService`, `MetricsService`, `HybridRouteResolver`, `VertexAIService`, `GroundedRouteService`, `AgentOrchestrationService`, and `OracleVectorSearchService`.
- In SQLSpec `0.69.0` (`src/app/lib/settings/_database.py`), `fetch_lobs` defaults to `False`, so `python-oracledb` bypasses `LOB` locators and returns CLOB/BLOB payloads under 1 GB directly as inline Python `str` and `bytes` values across both `select` and `select_stream`. `DatabaseSettings.create_config()` / `get_config()` enables `driver_features={"enable_session_tracing": True}`, wire-level `sqlcommenter` (`enable_sqlcommenter=True`, `sqlcommenter_enable_context=True`, `sqlcommenter_enable_traceparent=True`), `ObservabilityConfig`, and Autonomous mTLS `wallet_zip` (`extract_oracle_wallet_zip` and `parse_tnsnames_ora`).
- `DatabaseSettings.get_queue_config()` (`min=1, max=4`, `session_key="queue_db_session"`, `"manage_lifespan": True`, `driver_features={"fetch_lobs": False, "enable_session_tracing": True}`) isolates `OracledbAsyncQueueStore`'s dedicated background worker pool and in-place `driver_features` / `extension_config` mutations from the primary application pool (`config.db`).
- Domain database services inherit from `OracleLoaderService` (`self.get_sql("<name>")` backed by `default_sql_loader()`) or `OracleAsyncService` in `src/app/lib/service.py`. Static SQL lives in `src/app/db/sql/*.sql` as named queries, simple CRUD uses SQLSpec `sql.insert` / `sql.update` / `sql.delete` builders, and Oracle Text `CONTAINS` expressions are sanitized through `build_oracle_text_query` and `build_oracle_proximity_query` in `src/app/lib/text_search.py`.
- List endpoints use `create_filter_dependencies` in controllers and `list_with_count(*filters)` in services for pagination and filter wiring.
- Product vectors, `chat_route` vectors, and embedding-cache vectors are `VECTOR(3072, FLOAT32)` values generated by `gemini-embedding-2`.
- Oracle feature-demo metadata belongs inline in the baseline DDL (`src/app/db/migrations/0001_cymball_coffee_products.sql`). Keep `COMMENT ON` statements for compatibility and add 26ai `ANNOTATIONS(...)` on documented table, column, and normal-index surfaces; do not create follow-up migrations or separate `ALTER ... ANNOTATIONS(...)` statements just because local SQL parsers lag Oracle syntax.
- AI conversation and session persistence uses SQLSpec named queries in `src/app/db/sql/ai-runtime.sql` backing `OracleSessionStore` and `OracleEventStore` (`agent_session`, `agent_event`). Litestar browser sessions use `app_session`.
- Chat uses `AgentOrchestrationService` with single-query Oracle 26ai Hybrid RRF routing (`HybridRouteResolver.resolve_turn` -> `hybrid-search-turn` + `hybrid-term-hits` in `src/app/db/sql/hybrid.sql`). Re-entrant `AgentRuntime.execute_turn()` executes open-ended turns with prompt fencing (`<ACTIVE_SESSION_CONTEXT>`), parallel tool dispatch (`execute_parallel()`), and turn/step limits.
- Agent tools are closure-bound per request with `CallContext`, receiving request-scoped services through `ctx.services` (`CoffeeToolContext`) and `ctx.state` rather than global singletons.
- `/api/chat/stream` is an SSE endpoint adapted via `AgentStreamService`. It streams structured event frames (`session`, `tool_call`, `tool_end`, `delta`, `ping`, `final`), emitting keep-alive pings every 5 seconds to prevent connection drops.
- Chat page history is hydrated via `AgentOrchestrationService.get_display_history()`, returning `ChatMessage` instances with `.source` (`human` or `ai`) and `.message`.
- The chat sidebar clear button deletes the session and events in `OracleSessionStore` and `OracleEventStore` and clears only the Litestar chat session bridge keys. It does not clear menu data, metrics, response cache, or embedding cache.
- Multi-protocol machine endpoints: `LitestarMCP` mounts at `POST /mcp` with skill/prompt controllers and route-annotated tools (`mcp_tool="get_product"`, `mcp_tool="get_store_inventory"`, `mcp_tool="search_products"`); `LitestarA2A` mounts at `POST /a2a` with JSON-RPC agent execution (`CoffeeAgentExecutor`) and public discovery at `GET /.well-known/agent-card.json`; `ApexAIController` (`src/app/domain/products/controllers/_apex_ai.py`) mounts an OpenAI-compatible Vertex AI gateway at `GET /api/apex/ai/v1/models` and `POST /api/apex/ai/v1/chat/completions` (`http://host.docker.internal:8000/api/apex/ai/v1`, optional `APEX_GATEWAY_API_KEY`) for Oracle APEX 26.1 Generative AI Services.
- Store, location, and inventory work stays in the products domain: seed coordinates, Dallas, and curated inventory; route store answers from service facts.
- Store selectors and inventory UI must be driven by `StoreService` and fixture data. Do not hardcode a few store IDs in Jinja as presets; that narrows the demo to those locations and drifts from the seeded store list.
- Store-aware product RAG must vary or bypass response-cache reads whenever safe location or store context is present, so one store's inventory answer is not reused for another store.
- Maps URLs are the keyless baseline. Browser coordinates are opt-in and request-scoped; embeds require a separate restricted Maps Embed key.
- Frontend pages are HTMX + Jinja + Tailwind v4 + vanilla JavaScript / ApexCharts through `litestar-vite` template mode, not a standalone SPA.
- `src/resources/` is the Vite and npm project root. Keep `package.json`, `package-lock.json`, `tsconfig.json`, `vite.config.ts`, `public/`, and `node_modules/` there; Python `ViteConfig.paths.root` must point at the same directory.
- Explore-only educational calculators stay client-only in `src/resources/*.js` and wire to Jinja markup through `data-*` attributes as vanilla Vite-bundled JavaScript.
- Vector footprint estimates (`src/resources/vector-calculator.js`) compute raw bytes by format (`N * d * 8` for FLOAT64, `N * d * 4` for FLOAT32, `N * d` for INT8, `N * ceil(d / 8)` for BINARY), HNSW index and SGA Vector Pool bytes (`round(rawSize * 1.25 + N * 640)`, matching Oracle's ~1.3x FLOAT32 rule of thumb while preserving neighbor-graph link overhead on INT8/BINARY), IVF disk index (`round(rawSize * 1.1)`) and SGA centroid cache (`~sqrt(N)` centroids), and optional `CTXSYS.CONTEXT` FTS overhead; use `DBMS_VECTOR.INDEX_VECTOR_MEMORY_ADVISOR` for exact database-side HNSW/IVF sizing.
- EXPLAIN PLAN uses two named SQL calls: one `EXPLAIN PLAN FOR ...` and one `DBMS_XPLAN.DISPLAY()` read.
- `coffee` is the app CLI (`src/app/cli/`). Keep `bulk-embed`, `export-fixtures`, `load-fixtures`, `clear-cache`, `model-info`, `upgrade`, `configure-apex-cdn`, `worker`, `queues`, and `run` visible there.
- Keep public CLI modules declarative. Large workflows belong in focused private `src/app/cli/_helpers/` modules; small command-local helpers live in `src/app/cli/commands.py`. Do not add compatibility shim or facade modules.
- `sanitize_for_json` (`src/app/utils/serialization.py`) camel-cases `msgspec.Struct` keys for wire encoding. In the chat domain (`AgentOrchestrationService` and grounding formatting helpers), check both `snake_case` and `camelCase` keys using `_get_field(row, snake_name)` to remain resilient to case conversion differences between unit test mocks and runtime database responses.
- Product availability lookups (`PRODUCT_AVAILABILITY` in `src/app/domain/chat/services/_grounded.py`) resolve the target product from the turn's Hybrid RRF `turn_context.products` via exact candidate-name substring match first, then `extract_product_query(query)` phrase extraction, then pronoun follow-up resolution from `last_products` in session state, and finally the top Hybrid RRF product candidate (matching partial names such as `'Gemini'` -> `'Gemini Rush'` to `find-stores-with-product-inventory` by `product_id` before falling back to `find-product-availability-by-query`).
- ORDS Stateless Deployment on Cloud Run: Deploy ORDS on Cloud Run stateless, peered via Direct VPC, utilizing Secret Manager for the database system password (`DATABASE_SYSTEM_PASSWORD`) to enable automatic schema registration and validation on container boot.
- Oracle CDN for APEX Assets: Set `IMAGE_PREFIX` to Oracle's public APEX CDN (`https://apex.oracle.com/i/` or version-specific URL) via `src/app/db/sql/deploy/configure-apex-cdn.sql` (`src/app/cli/_helpers/ords.py`). This keeps the ORDS container stateless and avoids mounting static asset directories or using Cloud Storage FUSE.
- Image Re-hosting for Private Deployments: When deploying to Cloud Run in restricted environments where external registry authentication is unavailable or unreliable at deployment time, re-host official images in GCP Artifact Registry.
- AutoREST Table Enablement: Utilize Oracle ORDS `AutoREST` capability to expose database tables as REST endpoints directly via SQLSpec migrations or startup PL/SQL calls (`ORDS.ENABLE_SCHEMA` / `ORDS.ENABLE_OBJECT`), providing a zero-code private data access path.
- Naming a query parameter argument `query` in a Litestar controller action causes Litestar to pass the entire query parameters `MultiDict` to it. Use a different Python argument name (such as `search_query` or `q`) and map it explicitly using `Annotated[..., QueryParameter(name="query")]` from `litestar.params` to avoid this.
- Domain autowiring: Use `litestar-autowire[dishka,queues]` (`AutowirePlugin(AutowireConfig(domain_packages=["app.domain"], integrations=["dishka", "queues"]))` in `src/app/server/plugins.py`) for declarative controller and task discovery plus automatic `DishkaRouter` resolution; clear test cache with `clear_autowire_cache()`.
- Background workers: Use `litestar-queues` `0.12.0+` with separate persistence, placement, wakeups, and task events. Adopt unified CLI runners (`coffee run --no-worker`, `coffee worker run`, `coffee worker status`), dedicated queue maintenance CLI (`coffee queues ...`), bounded maintenance loops, and request-scoped Dishka DI per task invocation.
- Oracle Transactional Event Queues (`txeventq`): Configure native Oracle 26ai transactional queuing in SQLSpec via `sqlspec.adapters.oracledb.events.OracleAsyncTxEventQEventBackend` using `extension_config={"events": {"backend": "txeventq", "aq_queue": "COFFEE_EVENTS_QUEUE"}}`.
- Stateless Security & MCP: Separate Authentication (`auth=`, `SecureController`, `PublicController`) from Authorization (`guards=[...]`), enforced by `tools/ci/check_litestar_security.py`, and expose route-marked endpoints (`mcp_tool=`, `mcp_resource=`) via stateless `POST /mcp` with `litestar-mcp`.
- HTMX 2.x & `litestar-htmx`: Import strictly from `litestar_htmx`, never deprecated `litestar.plugins.htmx`. Reserve `HTMXTemplate` for partial fragments setting HTMX headers (`push_url`, `re_swap`, etc.); full pages return standard `Template`. Use `hx-ext="ignore:<extension>"` to break inherited extension parsing on subtrees.
