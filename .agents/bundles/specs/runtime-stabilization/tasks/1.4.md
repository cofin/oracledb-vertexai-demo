## Objective

Fix defects `CP-07`, `CP-08`, `CP-10`, `CP-11`, `PL-04`, `PL-05`, and `PL-14` by:
1. Fixing `GET /api/vector-search` in `src/app/domain/products/controllers/_vector.py:168-207` so the query string parameter is bound via `q: Annotated[str, QueryParameter(name="query", min_length=1, max_length=500)]` (avoiding Litestar's reserved `query` argument collision) and `limit` is bounded with `QueryParameter(name="limit", ge=1, le=20)`.
2. Updating `vector-search-products` and `explain-plan-vector-search` in `src/app/db/sql/products.sql` to `ORDER BY VECTOR_DISTANCE(embedding, :query_vector, COSINE) FETCH APPROX FIRST :limit ROWS ONLY` so Oracle 26ai uses the `product_embedding_idx` HNSW index, and removing `embedding` from `get-product` (`products.sql:4-16`).
3. Raising `AIServiceUnconfigured` (mapped to HTTP 503) when `GOOGLE_CLOUD_PROJECT` is unset or a placeholder (`"demo-project"`, `"your-project-id"`, `"placeholder"`) and `GOOGLE_API_KEY` is not set (`src/app/ioc.py`).
4. Deleting the stale unused `src/tests/unit/app/domain/chat/services/conftest.py`.

## Context

- `src/app/domain/products/controllers/_vector.py:173-175` defines `query: FromQuery[str]`, which collides with Litestar's reserved `query` scope injection and fails with HTTP 400 (`CP-08`, `PL-05`).
- `src/app/db/sql/products.sql:71-80` orders by `similarity_score DESC` and uses `FETCH FIRST :limit ROWS ONLY`, forcing an exact full-table scan instead of an HNSW approximate index traversal (`CP-07`).
- `src/app/ioc.py:72` defaults `project = settings.google_cloud_project or "demo-project"` and ignores placeholder values, so unconfigured environments fail late with a 500 error from Vertex AI instead of the documented HTTP 503 (`AIServiceUnconfigured`, `PL-04`).
