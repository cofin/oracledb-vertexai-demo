## Objective

Fix defects `CP-07`, `CP-08`, `CP-10`, `CP-11`, `PL-04`, `PL-05`, and `PL-14` by:
1. Fixing `GET /api/vector-search` in `src/app/domain/products/controllers/_vector.py:168-207` so the query string parameter is bound via `q: Annotated[str, Parameter(query="query", min_length=1)]` (avoiding Litestar's reserved `query` argument collision) and `limit` is bounded with `Parameter(ge=1, le=20, default=5)`.
2. Updating `vector-search-products` and `find-similar-products` in `src/app/db/sql/products.sql:71-95` to `ORDER BY VECTOR_DISTANCE(embedding, TO_VECTOR(:query_vector, 3072, FLOAT32), COSINE) FETCH APPROX FIRST :limit ROWS ONLY` so Oracle 26ai uses the `product_embedding_idx` HNSW index, and removing `embedding` from `get-product` (`products.sql:4-16`).
3. Raising `AIServiceUnconfigured` (mapped to HTTP 503 via `ai_service_exception_handler`) when `GOOGLE_CLOUD_PROJECT` is unset or a placeholder (`"demo-project"`, `"your-project-id"`, `"placeholder"`) and `GOOGLE_API_KEY` is not set (`src/app/ioc.py:67-84`).
4. Updating the `literalinclude` snippet or documentation in `docs/reference/api.md` and deleting the stale unused `src/tests/unit/app/domain/chat/controllers/conftest.py`.

## Context

- `src/app/domain/products/controllers/_vector.py:173-175` defines `query: FromQuery[str]`, which collides with Litestar's reserved `query` scope injection and fails with HTTP 400 (`CP-08`, `PL-05`).
- `src/app/db/sql/products.sql:71-80` orders by `similarity_score DESC` and uses `FETCH FIRST :limit ROWS ONLY`, forcing an exact full-table scan instead of an HNSW approximate index traversal (`CP-07`).
- `src/app/ioc.py:72` defaults `project = settings.google_cloud_project or "demo-project"` and ignores `settings.google_api_key`, so unconfigured environments fail late with a 500 error from Vertex AI instead of the documented HTTP 503 (`AIServiceUnconfigured`, `PL-04`).
