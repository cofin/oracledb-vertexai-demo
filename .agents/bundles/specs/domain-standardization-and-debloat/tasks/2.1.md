## Objective

Refactor `src/app/domain/system/` and `src/app/db/sql/system.sql` to use atomic Oracle `MERGE INTO` cache upserts, disjoint metric comparison windows, `FrozenBaseStruct` / `CamelizedFrozenStruct` schemas, and focused `OracleLoaderService` subclasses (`_cache.py`, `_personas.py`, `_metrics.py`), removing `_health.py`, `from app.config import db_manager` imports, and the `ResponseCacheService` / `SystemService` aliases.

## Context

- `src/app/db/sql/system.sql:1-77` currently performs non-atomic `DELETE` + `INSERT` writes for `response_cache` and `embedding_cache` and uses overlapping `SYSTIMESTAMP - NUMTODSINTERVAL(:hours, 'HOUR')` windows when computing metric deltas.
- `src/app/domain/system/services/_cache.py:1-143` and `_health.py:1-197` import `from app.config import db_manager` directly, call `json.loads` / `json.dumps` instead of `app.utils.serialization`, combine `PersonaManager` and `MetricsService` inside `_health.py` (which contains zero health endpoints because `/health` lives on `SystemController`), and export legacy `ResponseCacheService` and `SystemService` aliases.
- `src/tests/unit/db/test_named_sql.py` scans domain services for named SQL call sites; updating its AST visitor to recognize `self.get_sql("<name>")` and `loader.get_sql("<name>")` alongside `db_manager.get_sql("<name>")` keeps named-SQL parity checking green across all `OracleLoaderService` migrations.
