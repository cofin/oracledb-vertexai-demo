## Objective

Complete the domain standardization across `src/app/domain/products/` and `src/app/domain/web/`, extract `OracleVectorSearchService` into `products/services/_vector.py` with mypyc-safe post-`except:` SQLSpec fallback recommendations and `hybrid_rrf_ready` inspection, move pure async batch embedding into `VertexAIService.embed_missing_products` so background jobs no longer import Rich CLI helpers, and delete `_inventory.py`, `_vector_helpers.py`, `MapsService`, `EmbeddingService`, `chat/{exceptions,session}.py`, `BaseStruct` / `CamelizedBaseStruct`, and `pyproject.toml:305-313` `banned-api` ignores.

## Context

- `src/app/domain/products/services/_products.py` manually executes separate count + select SQL instead of `SQLSpecAsyncService.paginate_limit_offset` and duplicates Oracle Text escaping now provided by `app.lib.text_search`.
- `src/app/domain/products/jobs.py:1-50` (`products.embed_missing` worker task) imports `src/app/cli/_helpers/embeddings.py`, coupling background queue workers to Rich terminal progress bars.
- `src/app/domain/products/controllers/_apex.py:134-145` executes fallback SQLSpec queries *inside* an `except Exception:` block — under `sqlspec[mypyc]`, active `sys.exc_info()` inside `except:` can trip compiled C frames. Moving recommendation/fallback orchestration into `OracleVectorSearchService.recommend_for_apex(...)` in `_vector.py` and executing fallback SQL *after* the `try...except` block fixes both controller bloat and mypyc safety.
- All external callers of `InventoryService`, `MapsService`, `EmbeddingService`, `chat.exceptions`, `chat.session`, `BaseStruct`, and `CamelizedBaseStruct` were migrated in Tasks `2.1`–`2.3`, so they can now be deleted cleanly alongside lines `305-313` of `pyproject.toml`.
