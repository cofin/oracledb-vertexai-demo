## Objective

After every ADB wallet export, ADMIN connects over the wallet and idempotently provisions the app schema: the user with unlimited `DATA` quota, roles `CONNECT, RESOURCE, CONSOLE_DEVELOPER, DWROLE, DB_DEVELOPER_ROLE`, `EXECUTE ON DBMS_CLOUD_AI`, an HTTP ACE for `generativelanguage.googleapis.com`, and `ORDS.ENABLE_SCHEMA`. ADMIN, app, and wallet passwords are checked against the ADB policy before any container mutation. `uv run coffee upgrade` then succeeds against ADB-Free.

Reuse the statement shapes, the ORA-28007 unlock path, and the 24 x 5-second connection retry. Drop `MPACK_OEE` (out of scope) and the debug prints that leaked password fragments.
- README recipe (research F6) plus D9 additions: `DB_DEVELOPER_ROLE` nests `CTXAPP` for the `CTX_DDL` calls in migration 0001 (F14); Select AI needs `GRANT EXECUTE ON DBMS_CLOUD_AI` and an HTTP ACE, while `DWROLE` already covers `DBMS_CLOUD` (F12).
- ADB password policy (F3): ADMIN and app passwords are 12-30 characters with at least one upper, one lower, and one digit, and must not contain the username; the wallet password has at least 8 characters mixing letters with digits or specials. Double quotes are rejected because statements quote the password.
- Task 1.1 left `OracleDatabase._post_start_adb()` as an empty hook and `_preflight_adb()` checking only the legacy container.
- `tools/oracle/adb.py` uses top-level imports, so `import oracledb` sits at module top.
