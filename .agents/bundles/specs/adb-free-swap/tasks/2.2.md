## Objective

Settle what `INMEMORY PRIORITY HIGH` on `product`, `response_cache`, `embedding_cache`, and `chat_route` does on ADB-Free. Either the column store is available and population is verified in `V$IM_SEGMENTS`, or the reason it stays empty is documented with evidence. Both outcomes end with acceptance tests that pin the observed behavior.

## Context

- Migration 0001 marks those four tables `INMEMORY PRIORITY HIGH`. On today's gvenzl container `inmemory_size=0`, so they never populate.
- Research F11: Autonomous AI Database enables In-Memory through the console or API (percentage of SGA, ECPU model), not through ADMIN SQL; the free container has no console. Expected result: `inmemory_size = 0`, and ADMIN cannot change it.
- Research F15: `INMEMORY` clauses executed on ADB-Free in June without failing migrations.
- `V$IM_SEGMENTS` lists only populated segments (`OWNER`, `SEGMENT_NAME`, `POPULATE_STATUS`, `BYTES_NOT_POPULATED`, `INMEMORY_SIZE`); `DBA_TABLES` has `INMEMORY` and `INMEMORY_PRIORITY`.
- Task 2.1 provides `adb_env`, `adb_admin_connection`, `adb_app_connection`, and `make test-adb`. Task 1.1 Notes hold the first parameter readings.

## Steps

- [ ] **Step 1 (Baseline)**: `make test-adb` green; record the result.
- [ ] **Step 2 (Probe)**: As ADMIN over the wallet, run and record in Notes (exact output and ORA codes):
  ```sql
  SELECT name, value FROM v$parameter
   WHERE name IN ('inmemory_size', 'inmemory_force', 'inmemory_query', 'sga_target', 'cpu_count');
  SELECT table_name, inmemory, inmemory_priority FROM dba_tables
   WHERE owner = 'APP' AND table_name IN ('PRODUCT', 'RESPONSE_CACHE', 'EMBEDDING_CACHE', 'CHAT_ROUTE')
   ORDER BY table_name;
  SELECT segment_name, populate_status, bytes_not_populated, inmemory_size FROM v$im_segments
   WHERE owner = 'APP' ORDER BY segment_name;
  ALTER SYSTEM SET INMEMORY_SIZE = 256M SCOPE = BOTH;
  ```
  Before the `V$IM_SEGMENTS` query, run `SELECT /*+ FULL(t) NO_PARALLEL */ COUNT(*) FROM <table> t` as APP for each of the four tables, so priority-based population has a trigger.
- [ ] **Step 3 (Outcome)**: Follow exactly one branch based on Step 2.
  - **Branch B (expected): `inmemory_size` is 0 and the `ALTER SYSTEM` fails.** Add to `src/tests/integration/db/test_adb_free.py`: `EXPECTED_INMEMORY_ENABLE_ERROR = <recorded ORA code as int>` and `INMEMORY_TABLES = ("CHAT_ROUTE", "EMBEDDING_CACHE", "PRODUCT", "RESPONSE_CACHE")`; `test_inmemory_column_store_is_unavailable_on_adb_free(adb_admin_connection)` asserts `inmemory_size == "0"` and that the `ALTER SYSTEM` raises `oracledb.DatabaseError` with that code; `test_inmemory_tables_keep_attribute_but_do_not_populate(adb_admin_connection, adb_app_connection)` asserts the recorded `INMEMORY`/`INMEMORY_PRIORITY` values for the four tables (the exact strings observed in Step 2) and that `V$IM_SEGMENTS` has no `APP` rows after full scans.
