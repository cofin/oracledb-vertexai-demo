## Steps

- [ ] **Step 1: Create `.agents/bundles/knowledge/architecture/knowledge-catalog.md` and link it in `.agents/bundles/knowledge/index.md`**
  Create `.agents/bundles/knowledge/architecture/knowledge-catalog.md` with OKF v0.2 frontmatter covering:
  1. **Three-Tier Context Architecture**:
     - Tier 1: **Oracle 26ai Native `ANNOTATIONS(...)`** (`USER_ANNOTATIONS_USAGE`) defined in `0001_cymball_coffee_products.sql` (`Display`, `Description`, `Data_Role`, `Privacy`, `Embedding_Model`, `Embedding_Dimensions`, `Enum_Values`, `AI_Surface`, `Maps_Baseline`).
     - Tier 2: **Google Cloud Knowledge Catalog (`dataplex.googleapis.com/v1`)** Custom Entries (`oracle:cymbal-coffee:{product,store,store_product_inventory}`), Global System Aspects (`655216118709.global.{schema,overview,guidelines,queries}`), Business Glossary terms, and `lookupContext` retrieval.
     - Tier 3: **Open Knowledge Format (`OKF v0.2`)** in `.agents/bundles/knowledge/catalog/` and `src/app/db/fixtures/knowledge_catalog_context.json` providing `< 2ms` offline-capable grounding and full parity with `GoogleCloudPlatform/knowledge-catalog`.
  2. **CLI Lifecycle (`uv run coffee sync-catalog`)**:
     - Offline snapshot + OKF export: `uv run coffee sync-catalog --from-fixture --export-okf .agents/bundles/knowledge/catalog`
     - Live GCP upsert (`dataplex.googleapis.com/v1`): `uv run coffee sync-catalog --push`
  3. **Runtime & MCP Surfaces**:
     - `GET /api/catalog/context` (`mcp_tool="lookup_knowledge_catalog"`)
     - `GET /api/catalog/entries`
     - Prebuilt Dataplex MCP Toolbox server (`toolbox --prebuilt dataplex --stdio`) in `tools/lib/utils.py`.

  Add a link to `architecture/knowledge-catalog.md` in `.agents/bundles/knowledge/index.md`.

- [ ] **Step 2: Add Knowledge Catalog & "Breaking the Context Ceiling" demo slides to `SLIDES.md`**
  Append two slides to `SLIDES.md`:
  - **Slide — Oracle 26ai `ANNOTATIONS` $\rightarrow$ Google Cloud Knowledge Catalog (`lookupContext`)**:
    Shows how DDL-level `ANNOTATIONS(...)` in Oracle 26ai (`product`, `store`, `store_product_inventory`) are harvested by `uv run coffee sync-catalog` into Knowledge Catalog Global System Aspects (`655216118709.global.{schema,overview,guidelines,queries}`) and OKF v0.2 bundles, then retrieved at runtime via `lookupContext`.
  - **Slide — Live Demo Script: "Breaking the Context Ceiling" (Grounding OFF vs. ON)**:
    Walks through the 3-act live demo:
    1. **Act 1 (`Knowledge Catalog: OFF`)**: Ask an ambiguous availability/governance question (e.g., *"Can you reserve the last bag of Highland Silk in Dallas and save my GPS coordinates for next time?"*). Without catalog steward guidelines and `Privacy` annotations, the ungrounded prompt lacks explicit `low_stock` thresholds and coordinate non-persistence policies.
    2. **Act 2 (`Knowledge Catalog: ON` + `K` Telemetry Badge)**: Toggle **Knowledge Catalog Grounding `ON`** in the sidebar and re-run. Click the green **`K` (`Knowledge Catalog`)** telemetry chip on the reply to open the Context X-Ray popover showing the matched `oracle:cymbal-coffee:*` entry URIs (`oracle:cymbal-coffee:product`, `oracle:cymbal-coffee:store`, `oracle:cymbal-coffee:store_product_inventory`), active `Privacy` rules (`store.latitude/longitude`, request-scoped browser geolocation), `Stock Status` glossary definitions (`low_stock: 1 <= quantity <= 5`), and the `dataplex.googleapis.com/v1:lookupContext` YAML bundle.
    3. **Act 3 (`LitestarMCP` & `kcmd` / OKF v0.2 Parity)**: Show `POST /mcp` (`lookup_knowledge_catalog`) and `.agents/bundles/knowledge/catalog/index.md` demonstrating that the exact same OKF v0.2 knowledge format powers both developer coding agents and runtime customer-facing AI agents.
