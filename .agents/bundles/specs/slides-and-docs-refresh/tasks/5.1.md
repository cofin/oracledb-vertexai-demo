## Objective

Update `SLIDES.md` so the presentation accurately reflects the stabilized native `google-genai` + `litestar-mcp` architecture and highlights how **Oracle 26ai Hybrid Search with Reciprocal Rank Fusion (RRF)** and **BM25-style lexical ranking (Oracle Text `CONTAINS`/`SCORE`)** replace the separate LLM intent-classifier call and extra retrieval round trip.

## Context

- `SLIDES.md` currently depicts a 2-step pipeline (`FlashLiteIntentClassifier` LLM call $\rightarrow$ separate vector search) and references Google ADK and `gemini-2.5-flash`.
- The updated narrative shows:
  1. **Before vs After**: Two serial round trips (LLM classifier + vector search, ~350–500 ms overhead) vs **One Hybrid RRF SQL Query** (`hybrid-search-turn`, ~15–25 ms in Oracle 26ai) fusing `chat_route`, `product`, and `coffee_store`.
  2. **Why Lexical + Vector Matters**: Dense embeddings (`gemini-embedding-2`, 3072 dims) capture semantic vibe (`"bright citrus morning pour-over"`), while BM25-style lexical ranking (`CTXSYS.CONTEXT` `CONTAINS`/`SCORE` with `MULTI_COLUMN_DATASTORE`, plus Oracle 26ai `VECTOR(..., SPARSE)` for external BM25/SPLADE models) captures exact tokens (`"decaf"`, `"75208"`, `"Bishop Arts"`, SKU names).
  3. **Reciprocal Rank Fusion (RRF) Formula**:
     $$\text{RRF}(d) = \frac{w_{\text{lex}}}{60 + r_{\text{lex}}(d)} + \frac{w_{\text{vec}}}{60 + r_{\text{vec}}(d)}$$
  4. **Appendix B (`"Do you carry Folgers?"`)**: Dense embeddings map `"Folgers"` to ~0.68 cosine similarity with dark roasts, whereas `hybrid-term-hits` (`JSON_TABLE` + `CONTAINS`) proves `term_hits["folgers"] == 0` in the same database turn—triggering deterministic off-menu handling without hardcoded brand blocklists.
