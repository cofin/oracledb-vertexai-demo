4. Adding a root `GET /health` alias alongside `GET /api/system/health` (`src/app/domain/system/controllers/_system.py`), cleaning up `src/app/server/asgi.py`, and adding `[tool.ruff.lint.flake8-tidy-imports.banned-api]` (`TID251`) to `pyproject.toml` banning `orjson`, `google.adk`, and `litestar.plugins.htmx`.

## Context

- In `litestar-security` 0.6.0, `PublicController` sets `exclude_from_csrf=True` on every route. Because `CoffeeChatController` uses cookie-backed browser sessions for chat history and location opt-in, its `POST` routes must explicitly set `opt={"exclude_from_csrf": False}` so CSRF is enforced when `DEBUG=False` (`PL-08`).
- Machine protocol clients calling `POST /mcp` and `POST /a2a` do not use browser cookies, so they must remain `exclude_from_csrf=True` and optionally authenticate via `X-API-Key: <MCP_API_KEY>`.

## Notes & Discoveries

- In `litestar-security` 0.6.0, `PublicController` (`auth = public()`) causes `_validate_csrf_metadata` to reject `opt={"exclude_from_csrf": False}`; setting `auth = exclude()` on `CoffeeChatController` bypasses auth while leaving native Litestar CSRF active on `opt={"exclude_from_csrf": False}` POST handlers.
- `ApexController`, `CoffeePromptController`, and `CoffeeSkillController` must explicitly declare `PublicController` / `opt = {"auth": public()}` so that when a non-default mechanism (`api-key`) is registered in `SecurityConfig`, `RouteCompiler` does not require an implicit default-participating mechanism on those routes.
