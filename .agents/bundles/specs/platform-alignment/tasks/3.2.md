## Objective

Align the domain service and Dishka DI package structure with reference platform conventions by:
1. Splitting `src/app/domain/products/services/services.py` (460 lines) into focused private modules (`_products.py`, `_embedding.py`, `_stores.py`, `_inventory.py`, `_maps.py`) re-exported in `src/app/domain/products/services/__init__.py`.
2. Splitting `src/app/domain/system/services/services.py` (195 lines) into `_health.py` (`SystemService`) and `_cache.py` (`ResponseCacheService`) re-exported in `src/app/domain/system/services/__init__.py`.
3. Splitting `src/app/ioc.py` into `src/app/ioc/{__init__,_config,_database,_ai,_domain}.py` (`ConfigProvider`, `DBProvider`, `AIProvider`, `DomainServiceProvider`, `get_providers`, `create_container`) with **no** `from __future__ import annotations` in any `src/app/ioc/*.py` module.
4. Adding `execute_many` helper on `OracleAsyncService` (`src/app/lib/service.py`) and request/worker container contextvars (`request_container_var`, `worker_container_var`) in `src/app/lib/di.py` and `src/app/cli/utils.py`.

## Context

- All callers import domain services from `app.domain.products.services` and `app.domain.system.services`, and import DI helpers from `app.ioc`. Replacing the monolithic files with private `_*.py` modules and package `__init__.py` re-exports preserves every public import path while keeping each module small and single-purpose.
- Dishka inspects provider type annotations at runtime, so `src/app/ioc/*.py` must never contain `from __future__ import annotations`.
