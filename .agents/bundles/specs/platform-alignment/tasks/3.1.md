## Objective

Resolve findings `PL-03`, `PL-06`, `PL-10`, and `PL-13` by:
1. Updating `pyproject.toml` to drop the `adk` extra from `sqlspec`, add explicit `google-genai>=1.68.0` and `tenacity>=9.0.0`, upgrade `litestar-mcp[a2a,google-genai,opentelemetry]>=0.15.0`, and remove stale ADK `filterwarnings`.
2. Splitting the monolithic `src/app/lib/settings.py` into `src/app/lib/settings/{__init__,_env,_app,_server,_database,_ai,_maps,_log,_otel}.py` while preserving all public exports (`Settings`, `AppSettings`, `ServerSettings`, `DatabaseSettings`, `AISettings`, `MapsSettings`, `LogSettings`, `OpenTelemetrySettings`, `get_settings`, `reload_settings`) and adding `ORACLE_AGENT_IN_MEMORY` (with fallback to `ORACLE_ADK_IN_MEMORY`) and `MCP_API_KEY: str | None = None`.
3. Fixing `src/app/lib/log/_middleware.py` so `get_settings()` is called inside `StructlogMiddleware.__init__` (not at module import time) and `http.response.start` uses `list(message.get("headers", []))`.

## Context

- `src/app/lib/settings.py` is 583 lines long and mixes `.env` parsing, Oracle database pool config, Vertex AI config, Maps config, logging config, and OpenTelemetry config in a single file.
- `src/app/lib/log/_middleware.py:13` executes `settings = get_settings()` at import time (`PL-06`), and line 93 accesses `message["headers"]` directly (`PL-10`), which fails with `KeyError` on ASGI `http.response.start` events that omit `headers`.
