## Objective

Implement the Litestar OpenAI-compatible Vertex AI gateway (`GET /api/apex/ai/v1/models` and `POST /api/apex/ai/v1/chat/completions`) in `ApexAIController(PublicController)` backed by `ModelClientProtocol` (`GeminiModelClient`) and `FrozenBaseStruct` OpenAI wire models so Oracle APEX 26.1 (`COFFEE_VERTEX_AI` in `--mode gateway`) can call Gemini 3.8 Flash without 60-minute OAuth token expiry or mTLS workstation client-certificate barriers.

## Context

- Oracle APEX 26.1's OpenAI Generative AI Service provider invokes `GET {base_url}/models` during "Test Connection" and `POST {base_url}/chat/completions` for `APEX_AI.GENERATE`, `APEX_AI.CHAT`, and App Builder AI Assistant requests.
- Because `APEX_AI` calls Litestar server-to-server via Oracle `UTL_HTTP` without browser cookies, `POST /api/apex/ai/v1/chat/completions` must set `opt={"exclude_from_csrf": True}` while optionally validating `Authorization: Bearer <key>` using `secrets.compare_digest` whenever `APEX_GATEWAY_API_KEY` is configured in the environment.
- Because `APEX_AI` consumes `/api/apex/ai/v1/*` as an OpenAI-compatible Generative AI Service (with union content parts and optional `text/event-stream` SSE) rather than an APEX REST Data Source Module, `tools/oracle/apex_catalog.py` excludes `/api/apex/ai/*` from `.agents/generated/apex-catalog.openapi.json` while Litestar's main OpenAPI schema tags `ApexAIController` under `"APEX AI Gateway"`.

## Steps

- [ ] **Step 1 (Red — Unit Tests in `src/tests/unit/domain/products/controllers/test_apex_ai_gateway.py`)**:
  1. Write unit tests verifying:
     - `OpenAIChatMessage`, `OpenAIChatCompletionRequest`, `OpenAIChatCompletionResponse`, `OpenAIChatCompletionChunk`, and `OpenAIModelList` inherit from `FrozenBaseStruct` (`frozen=True, gc=False`), support both string `content` and structured text-part arrays (`[{"type": "text", "text": "..."}]`) sent by OpenAI-compatible clients, and reject empty `messages` with HTTP `400`.
     - `GET /api/apex/ai/v1/models` returns `object="list"` containing `gemini-3.8-flash` and `google/gemini-3.8-flash` model cards.
     - `POST /api/apex/ai/v1/chat/completions` (`stream=False`) extracts `system` / `developer` messages into `system_instruction`, converts `user` and `assistant` (`role="model"`) messages into `Content` turns, strips any `"google/"` prefix from `model` before calling `ModelClientProtocol.generate_stream(...)`, aggregates text chunks and `Usage` token counts into an `OpenAIChatCompletionResponse` (`object="chat.completion"`, `finish_reason="stop"`), and succeeds without a browser CSRF cookie.
     - `POST /api/apex/ai/v1/chat/completions` (`stream=True`) streams `text/event-stream` SSE lines (`data: <OpenAIChatCompletionChunk JSON>\n\n` ending with `data: [DONE]\n\n`) serialized via `encode_json` from `app.utils.serialization`.
     - When `APEX_GATEWAY_API_KEY` is set, missing or mismatched `Authorization: Bearer ...` headers return HTTP `401` (`NotAuthorizedException`), while a matching Bearer token succeeds; when `ModelClientProtocol` raises `AIServiceUnconfigured` or credential errors, the endpoint returns a structured HTTP `503` diagnostic rather than an unhandled `500`.
  2. Run `uv run pytest src/tests/unit/domain/products/controllers/test_apex_ai_gateway.py -q -p no:cacheprovider` and confirm failure before implementation.
