## Objective

Implement `tools/oracle/apex_vertex.py` and `manage.py infra apex configure-vertex` so developers can connect Oracle APEX 26.1 inside `adb-free:latest-26ai` to **Direct Vertex AI** (`https://aiplatform.googleapis.com/v1/projects/{project}/locations/{location}/endpoints/openapi`, `model="google/gemini-3.8-flash"`, default `--mode direct`) or to the **Litestar OpenAI-compatible gateway** (`http://host.docker.internal:8000/api/apex/ai/v1`, `--mode gateway`), refresh OAuth2 Bearer tokens idempotently (`--refresh-token`), and verify round-trip generation via `APEX_AI.GENERATE` (`--verify`).

## Context

- Oracle APEX 26.1 supports OpenAI-compatible Generative AI Services (`Used by App Builder = Yes` and `APEX_AI.GENERATE(p_prompt => ..., p_service_static_id => 'COFFEE_VERTEX_AI')`).
- Vertex AI exposes a first-party OpenAI-compatible Chat Completions endpoint at `https://aiplatform.googleapis.com/v1/projects/{project}/locations/{location}/endpoints/openapi` (`POST /chat/completions`), accepting `model="google/gemini-3.8-flash"` and `Authorization: Bearer <GCP_OAUTH2_ACCESS_TOKEN>`.
- Outbound HTTPS from `APEX_260100` / `APP` inside Oracle AI Database 26ai requires an explicit `DBMS_NETWORK_ACL_ADMIN.APPEND_HOST_ACE` entry for `aiplatform.googleapis.com` (port `443`, `http` privilege) in `direct` mode or `host.docker.internal` (port `8000`, `http` privilege) in `gateway` mode.
- Access tokens must never be printed to console output or written into tracked files.

  1. Write unit tests verifying:
     - `ApexVertexConfig.from_env(mode=ApexVertexMode.DIRECT)` builds `base_url == "https://aiplatform.googleapis.com/v1/projects/<project>/locations/<location>/endpoints/openapi"` (`locations/global/endpoints/openapi` when `VERTEX_AI_LOCATION="global"`), `model == "google/gemini-3.8-flash"`, `credential_static_id == "VERTEX_AI_CRED"`, and `service_static_id == "COFFEE_VERTEX_AI"`.

     - `ApexVertexConfigurator.configure()` executes parameterized PL/SQL bind variables (never string-interpolating tokens or passwords into SQL text) to: (a) resolve the installed `APEX_26%` schema and grant `DBMS_NETWORK_ACL_ADMIN.APPEND_HOST_ACE` for `APP` and `APEX_260100`, (b) set workspace `COFFEE` security group ID and upsert `VERTEX_AI_CRED` via `APEX_CREDENTIAL.CREATE_CREDENTIAL` + `APEX_CREDENTIAL.SET_PERSISTENT_CREDENTIALS(p_credential_static_id => :cred_id, p_key => 'Authorization', p_value => 'Bearer ' || :token)`, and (c) register/update the `COFFEE_VERTEX_AI` Generative AI Service (`Used by App Builder = Yes`).
     - `--refresh-token` updates `APEX_CREDENTIAL.SET_PERSISTENT_CREDENTIALS` without recreating ACLs or the AI service definition, and `--verify` invokes `APEX_AI.GENERATE(p_prompt => :prompt, p_service_static_id => :service_id)` and returns `ApexVertexResult` with non-empty verification output.
